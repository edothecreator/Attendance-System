1. PROJECT OVERVIEW
================================================================================

AttendAI is an automated attendance system that uses facial recognition to
identify students in class videos. Professors upload a video of their class,
and the AI identifies which students are present by comparing detected faces
against enrolled student embeddings. Students not detected are automatically
marked absent.

Target Institution: FST Marrakech (Faculté des Sciences et Techniques)
Class Structure: 1 class, 7 modules, 14 weeks per module


2. TECH STACK
================================================================================

Backend:
  - Python 3.12
  - FastAPI (async web framework)
  - SQLAlchemy 2.0 (async ORM)
  - PostgreSQL (hosted on Supabase)
  - JWT Authentication (python-jose + bcrypt)

AI/ML Engine:
  - DeepFace (facial recognition library)
  - Facenet512 model (512-dimensional face embeddings)
  - MTCNN (primary face detector)
  - OpenCV (fallback detector + video processing)
  - SSD (secondary fallback detector)

Frontend:
  - React 18 (Vite build tool)
  - Tailwind CSS (utility-first styling)
  - React Router v6 (client-side routing)
  - Axios (HTTP client)
  - WebSocket (real-time updates)

Infrastructure:
  - Supabase (managed PostgreSQL)
  - Docker Compose (local dev for Postgres/Redis)

  - id              UUID (PK)

  - created_at      TIMESTAMP

7. AI PIPELINE - HOW IT WORKS
================================================================================

ENROLLMENT FLOW:
  1. Admin uploads 3-10 photos of a student
  2. Each photo is validated (at least one face must be detected via MTCNN)
  3. DeepFace extracts a 512-dimensional embedding from each photo
  4. ALL individual embeddings are stored (not averaged)
  5. First photo (or selected one) becomes the profile picture

  Why multiple embeddings?
  → Different angles/lighting create different vectors
  → Matching against 5-10 vectors is far more robust than 1 averaged vector
  → If ANY stored embedding matches the video face, the student is recognized

IDENTIFICATION FLOW (Video Processing):
  1. Video is uploaded and saved to disk
  2. Background worker starts processing
  3. Frames extracted at 2 FPS (2 frames per second)
  4. Each frame is preprocessed:
     - Converted BGR → RGB
     - Upscaled if too small (< 640px)
     - Brightness/contrast auto-adjusted for dark frames (CLAHE)
  5. Face detection uses FALLBACK CHAIN:
     - Try MTCNN first (best accuracy for frontal faces)
     - If nothing found, try OpenCV Haar Cascade (catches different angles)
     - If still nothing, try SSD (good for distant/small faces)
  6. Each detected face (min 30x30px) gets a 512-d embedding via Facenet512
  7. Embedding compared against ALL stored embeddings using DUAL METRICS:
     - Cosine Similarity (threshold: 0.4)
     - Euclidean Distance (threshold: 30.0)
     - Match if EITHER metric passes
  8. Best confidence per student is kept (deduplicated)
  9. Results broadcast via WebSocket in real-time
  10. All students marked: detected = present, not detected = absent

MATCHING ALGORITHM:
  For each face detected in video:
    For each stored embedding in database:
      cosine_score = dot(face, stored) / (norm(face) * norm(stored))
      euclidean_dist = L2_norm(face - stored)
      
      if cosine_score >= 0.4 OR euclidean_dist <= 30.0:
        → MATCH (keep best score per student)

  Confidence = combined score from both metrics


8. BUSINESS RULES
================================================================================

Sequential Weeks:
  - Professors must take attendance in order (Week 1, then 2, then 3...)
  - Cannot skip to Week 3 without completing Week 1 and 2
  - CAN retake any previously completed week (overwrites old data)
  - Admin can bypass this restriction

Module Ownership:
  - Each professor is assigned to exactly one module
  - They can ONLY upload videos for their assigned module
  - They can ONLY view sessions for their module
  - Admin has access to all modules

Attendance Logic:
  - When a video is processed, ALL enrolled students get a record
  - Detected in video → is_present = True + confidence score
  - Not detected → is_present = False
  - Retaking a week deletes the old session and all its attendance records

10. SETUP & INSTALLATION
================================================================================

Prerequisites:
  - Python 3.12+
  - Node.js 18+
  - PostgreSQL (or Supabase account)

Backend Setup:
  cd attend-ai/backend
  pip install -r requirements.txt
  pip install tf-keras                    # Required for TensorFlow 2.21+
  
  # Configure database URL in .env
  # Then initialize:
  python init_db.py
  
  # Start server:
  python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000

Frontend Setup:
  cd attend-ai/frontend
  npm install
  npm run dev
  
  # App available at http://localhost:5173

Environment Variables (.env):
  DATABASE_URL=postgresql+asyncpg://user:pass@host:5432/dbname
  REDIS_URL=redis://localhost:6379/0
  APP_HOST=0.0.0.0
  APP_PORT=8000
  CORS_ORIGINS=http://localhost:5173
  FACE_MATCH_THRESHOLD=0.4
  FRAME_EXTRACTION_FPS=2

13. TIPS FOR BEST RESULTS
================================================================================

Enrollment Photos (3-10 per student):
  - Include frontal face (looking at camera)
  - Include slight left and right angles
  - Mix indoor and outdoor lighting
  - At least one photo similar to video quality
  - Clear, unobstructed face (no sunglasses, masks)
  - Different expressions (neutral, slight smile)

Video Recording:
  - Good lighting (avoid backlight)
  - Camera at face level or slightly above
  - Students should face camera at some point
  - Minimum 720p resolution recommended
  - Avoid excessive motion blur
  - 5-15 seconds is usually enough if faces are visible

Troubleshooting Low Detection:
  - Enroll with MORE photos (8-10 instead of 3)
  - Use photos taken in similar conditions to the video
  - Ensure video has adequate lighting
  - Lower FACE_MATCH_THRESHOLD in .env (try 0.35)
  - Increase FRAME_EXTRACTION_FPS (try 3)

15. SECURITY NOTES
================================================================================

- Passwords hashed with bcrypt (cost factor 12)
- JWT tokens expire after 24 hours
- CORS restricted to frontend origin
- File uploads validated (type + size limits)
- SQL injection prevented via SQLAlchemy ORM
- Profile images stored as base64 in DB (no file system exposure)
- SECRET_KEY should be changed in production (app/auth.py)
- Database credentials should use environment variables

Production Recommendations:
- Change SECRET_KEY to a random 64-char string
- Use HTTPS
- Set stricter CORS origins
- Add rate limiting
- Store videos in cloud storage (S3/GCS) instead of local disk
- Add proper logging and monitoring
